# 分词器 v2：按脚本预切分，再在片段内做 BPE

## v1 的问题

v1 的 BPE 把整句当作一条字符链（只在句末标点/换行处断句），合并约束只有
「最多 4 个字符」，于是会出现：

- 跨标点合并：「他抬」「起，」「。\n」这种谁也读不出来的 token；
- 中英混排合并：「AI技」「2024年」被当成一个整体，中英边界消失；
- 英文退化成字节：词表里没有英文字母的合并（v1 只统计单字符原子），
  `quick` 变成 `q` `u` `i` `c` `k` 五个 token。

这不是参数没调好，是 BPE 的机制决定的：**BPE 只按频次合并，不做语言学判断。**
前沿模型（GPT-4o 的 o200k、Llama 3 的 cl100k、Qwen 的 byte-level BPE）都在 BPE
前面加一层 **预切分（pre-tokenization）**，只允许同一段内合并。预切分是三阶段
（预切分 / 词表 / 合并）里对下游影响最大的一环（arXiv:2402.18376）。

## v2 的设计

1. 先按「脚本类别」切片段：
   - `cjk`：汉字（含扩展区）、假名、谚文；
   - `latin`：字母、数字（含 `AI`、`2024`）；
   - `punct`：标点，每字符一片；
   - `space`：空白，每字符一片，但**粘到后一个拉丁词**上（` quick` 这种前导空格风格）。
2. 片段内做 BPE 合并，**跨片段禁止合并**（用 `cuts` 把边界锁死）。
3. 片段内最大 token 长度：CJK 用 `max_token_chars`（默认 4）；拉丁用
   `min(24, max(8, 片段长度))`，保证一个普通英文词能完整成一个 token；标点/空白固定 1。
4. 训练和编码共用同一套 `split_pieces`，不会出现「训练时会、编码时不会」。
5. `meta` 里写 `pretokenize: "script_v2"`；没有这个标记的老 tokenizer 按 legacy 路径编码
   （整句字符链），所以旧断点仍可用。

## 实测（40 万字中文 + 600 行英文，词表 4096）

| 指标 | v1 | v2 |
|---|---:|---:|
| 压缩比（字符/token） | 1.34–1.38 | 1.30 |
| 跨标点 token | 180 个 | **0** |
| 中英混合 token | 20 个 | **0** |
| 英文 `The quick brown fox...` | `The / qui / ck / bro / w / ...` | `T / he /  quick /  brown /  fox /  jumps / ...` |

压缩比略低是预期内的：v1 靠跨边界合并「刷」出来的高压缩比，代价是 token 不成词；
v2 用 3% 左右的压缩比换干净的词边界。

## 换分词器 = 换断点

v2 的指纹（词表 + 合并规则）与 v1 不同，**旧断点不能直接续训**；升级后要重新
`lingyu prepare`，再从头训练。`train.meta.json` 里的指纹检查会在开跑前拦住不配套的
断点，不会出现「loss 照降、输出乱码」。

## 下一步

- 中文词表扩到 16k–32k 时，v2 的压缩比会明显回升（现在 8k 词表下很多词只能拆开）；
- 可选 BPE-dropout（训练时随机丢 10% 合并）提升正则性，列入路线图。
