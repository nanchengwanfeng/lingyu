# 灵语引擎成熟度评估：现在是不是玩具？差什么才能「毕业」

> 2026-10-31 整理。回答一个问题：**为什么它能跑通全流程，却仍然给人「教学演示玩具」的感觉？**
> 结论先说：玩具感不是来自参数少，而是来自 **没有定义「成功」、没有度量、没有燃料、没有出口**。
> 参数少只是结果，不是原因。

---

## 0. 结论（一句话版）

> 灵语目前是一个「**单卡教学级训练器**」：架构、训练、SFT、聊天、GUI、打包都真实可用，
> 但它**无法回答「这次改动让模型变强了吗」**——没有评测集、没有足量数据、没有可对外的模型产物。
> 于是它只能证明「流程是通的」，无法证明「模型是有用的」。这就是玩具感的来源。

---

## 1. 五个结构性差距（按致命程度排序）

### ① 没有评测体系 —— 最致命

现状：唯一的量化指标是验证集 loss / perplexity（且不同数据集不可横向比较）。
没有 C-Eval / CMMLU / MMLU 子集，没有对话质量 rubric，没有基准脚本，也没有把分数写进 CI。

后果：
- 改了学习率、模板、数据配比，**不知道是变好还是变坏**；只能看 loss 曲线「感觉降了」。
- 对外无法说「我们训的 47M 模型在 X 任务上达到 Y 分」——没有可引用的数字。
- loss 低 ≠ 会答题：13M/47.8M 的实验已经证明，SFT loss 2.3 时回答仍然跑偏。

> 这是「玩具」和「实验平台」的分水岭：**先有度量，才谈优化。**

### ② 训练量差 20～30 倍（欠训练）

| 模型 | 参数量 | 训练 token | tokens/参数 | Chinchilla 最优点（20×） |
|---|---:|---:|---:|---:|
| small（chat.ini） | 13.08 M | 7.89 M | **0.60** | 需要 262 M |
| medium | 47.80 M | 34.81 M | **0.73** | 需要 956 M ≈ 1 B |

后果：模型不是「小」，是**远远没喂饱**。哪怕参数量不变，把 47M 模型从 34.8M token
训到 1B token（约 **27 倍**），效果也会有质的变化——单卡 8GB 显存按实测约 45k tok/s，**约 6.2 小时**就能做到。
现在连这个最便宜的实验都没跑满过。

### ③ 数据是「几本书」，不是「数据流水线」

现状：`data1` = 10 本中文书（966 万字符）；SFT = Alpaca-GPT4-zh 翻译（4.8 万条）。
没有：去重（MinHash）、质量过滤、语言识别、领域配比、分片与 streaming、数据版本管理。
后果：数据规模停在千万 token 级，无法支撑 1B～10B token 的训练；数据一变，分词器指纹全变。

### ④ 系统能力是「单卡教学实现」

- 并行：只有单卡循环；FSDP2/DeepSpeed/Megatron 是**脚本生成**，不是引擎内真训练；
- 吞吐：纯 PyTorch eager，没有 flash-attn、fused 算子、torch.compile、CUDA Graph；
  47.8M 模型实测 45k tok/s，有效算力约 13 TFLOPS（远低于 8GB 卡上限）；
- 容错：无 elastic training、无断点 resharding、无多机通信验证；
- 显存：2.4 只做了梯度检查点与 8bit 优化器（−67% 峰值），没有 offload / ZeRO。

### ⑤ 没有出口（模型只能在灵语里看）

- 无 HF `safetensors` 导出、无 tokenizer 打包、无 model card；
- 无 GGUF / INT8 / INT4 量化，不能在 llama.cpp / Ollama 跑；
- 无推理服务（批量、KV 分页、OpenAI 兼容 API），只有单用户 CLI/GUI 聊天；
- 结果：训出来的模型是「灵语内部资产」，不是「可以交给别人的模型」。

## 2. 硬指标对照

| 维度 | 灵语现状 | nanoGPT（教学参考） | TinyLlama-1.1B | Qwen3-0.6B | 「可交付引擎」应有 |
|---|---|---|---|---|---|
| 参数量 | 13M～79M | 124M | 1.1B | 0.6B | 0.1B～ |
| 训练 token | 7.9M～34.8M | ~10B（OpenWebText 多 epoch） | 3T | 36T（Qwen3 全系） | ≥ 20×参数 |
| tokens/参数 | 0.6～0.73 | ~80 | ~2700 | ~60000 | ≥ 20 |
| 词表 | 8,192 | 50,257 | 32,000 | 151,936 | 32k～150k |
| 数据管线 | 10 本书 + 1 个 SFT 集 | 单数据集 | 多源+去重 | 万亿级、多语言、去重 | 去重/过滤/配比/分片 |
| 评测 | 只有 val loss | 无 | MMLU/C-Eval 等 | 全榜单 | 内置 eval harness |
| 并行 | 单卡 | 单卡 | 多机多卡 | 大规模 | FSDP/TP/PP/EP |
| 训练加速 | 纯 eager | 纯 eager | flash-attn/fused | 全套 | flash-attn/compile/FP8 |
| 导出 | 仅灵语 `.pt` | 无 | HF safetensors | HF + GGUF | HF/GGUF/ONNX |
| 推理服务 | CLI/GUI 单用户 | 无 | vLLM/llama.cpp | 全生态 | OpenAI API + 批量 |
| 工程 | 无 git/CI/覆盖率 | 有 git | 有 CI/发布 | 完整 | git + CI + 发布 |

> 注意：nanoGPT 也是「教学项目」，但它**只做教学**，从不宣称能产出可用模型。
> 灵语的尴尬在于：既做了教学产品，又用了「13M 到万亿参数」的叙事。

## 3. 成熟度阶梯（L0 → L3）

### L0 教学 Demo（现状）
- 单卡能跑通 train→sft→chat；GUI/打包/文档齐全；无评测、欠训练。
- **验收**：demo 级——「流程是通的」。

### L1 可复现实验平台（1～2 周，单卡即可）
必须补齐：
1. **评测脚本**：C-Eval 子集 / CMMLU 子集 / 困惑度 / 对话 rubric（人工 1～5 分）；
2. **数据版本**：语料清单 + 指纹 + 去重 + 过滤脚本，固定 train/val/test 划分；
3. **实验记录**：`run.json` 已有 → 增加「配置 + 数据版本 + 评测分数」三联表；
4. **确定性**：seed、断点 RNG 恢复（已有基础）、同配置重跑 loss 可复现。
- **验收**：能回答「A 配置比 B 好多少分」；任一实验可一键复现。

### L2 能产出「有点用」的小模型（2～4 周 + 租卡，数百～数千元级）
必须补齐：
1. **足量训练**：≥300M 参数 × ≥6B token（Chinchilla 最优）；
   8×A100 按 40% MFU 约 **3 小时**；单卡 8GB 不现实（约 6 天以上）；
2. **数据**：≥10B token 中文开源语料（SkyPile / WuDao / CCI 等）+ 去重过滤；
3. **导出**：HF safetensors + tokenizer + model card；GGUF 量化；
4. **推理验证**：llama.cpp 或 vLLM 能加载并对话（证明「模型是通用的」）；
5. **复现**：一键训练脚本 + 数据下载脚本 + 预期分数。
- **验收**：C-Eval 子集有非随机分数；对话主观可用率 > 50%（人工 rubric）。

### L3 生产级引擎（数月起）
必须补齐：真 FSDP2/TP/PP + 容错 resharding、MFU 指标与 profiling、插件内核 ABI、
OpenAI 兼容服务、CI/覆盖率/静态检查、跨厂商（ROCm/XPU/MPS）验证、代码签名/离线包。
- **验收**：别人能拿它训自己的模型并部署；有性能与质量基准报告。

## 4. 两条路线（先选定位，再谈缺什么）

**路线 A：教学/实验平台（推荐先走）**
- 差异化：从零手写、单卡可跑、GUI 友好、中文文档、诚实估算、可解释每一步；
- 目标：nanoGPT 的「中文单卡加强版」；不追求 SOTA，追求**可复现、可教学、可实验**；
- 关键补齐：L1（评测 + 数据版本 + 实验记录）——**1~2 周，不需要租卡**。

**路线 B：真·训练引擎**
- 差异化：单卡到多卡一套代码、显存优化、可导出可服务；
- 目标：L2 → L3；需要数据工程 + 分布式 + 租卡验证 + 工程化；
- 成本：数月全职或数人月；至少数千元 GPU 预算。

> 两条路不冲突，但**不能同时宣称**。现在的问题是想走 B 的叙事，却只有 A 的能力。

## 5. 「还差什么」行动清单（按性价比）

**P0（1～2 周，单卡）**
1. `lingyu eval`：C-Eval/CMMLU 子集 + PPL + 对话 rubric，输出 JSON 分数；
2. 数据流水线脚本：下载→去重→过滤→分片，固定划分并记录指纹；
3. 把 47.8M 模型训到 **1B token**（约 6.2 小时单卡），记录分数变化（0.73→20 tokens/param 的对照）。

**P1（2～4 周，需租卡）**
4. 300M 档配置 + 8 卡 FSDP2 真循环（先租 2 卡验证，再 8 卡）；
5. HF safetensors 导出 + GGUF 量化 + llama.cpp/vLLM 加载验证；
6. 断点 resharding + 容错（挂掉能续）。

**P2（持续）**
7. 吞吐：flash-attn / fused / torch.compile，产出 MFU 报告；
8. OpenAI 兼容推理服务 + GUI 接入；
9. 工程：git、CI、ruff/mypy、覆盖率、离线包、代码签名、跨平台。

## 6. 关键数字怎么来的（可复核）

- Chinchilla 最优点 ≈ **20 token/参数**；
- tokens/参数 = 训练 token ÷ 参数量：13.08M→0.60、47.8M→0.73；
- 1B token 单卡时间：1e9 ÷ 45,000 tok/s ≈ **6.2 小时**（medium 实测 45,723 tok/s）；
- 训练算力：`FLOPs ≈ 6 × N × D`；8×A100 按 40% MFU ≈ 1e15 FLOP/s；
  - 47.8M × 1B：6×4.78e7×1e9 ≈ 2.9e17 → 约 **290 秒**；
  - 300M × 6B：6×3e8×6e9 ≈ 1.08e19 → 约 **3 小时**；
- 有效算力（现状）：6 × 4.78e7 × 45,723 ≈ **1.3e13 FLOP/s**（约 13 TFLOPS，说明小模型+小 batch 下大量算力闲置）。

## 7. 关于「万亿参数」叙事

`lingyu launch` 能生成多机脚本，但引擎**不实现**分布式训练循环。这是诚实的边界，
但宣传上「一个引擎从 13M 到万亿参数」容易被读成「能训万亿」。建议口径改成：

> 「同一个配置语言与数据格式，小模型本机训；超过本机能力时，如实算给你听，并生成需要你自己补
> 几十行胶水的分布式脚本。」

---

## 8. 结语

**玩具不是贬义**：nanoGPT、karpathy 的 micrograd 都是教学项目，影响力远超很多「产品」。
真正的问题是**目标不清**：一面用「万亿参数」讲故事，一面又只有单卡教学实现。

所以「还差什么」的准确答案是：

> 差一个**明确的定位**（教学平台 or 真引擎）、
> 差一套**度量**（评测 + 实验记录）、
> 差一次**足量训练**（1B token 起步）、
> 差一个**出口**（HF/GGUF/推理服务）。

前两件 1～2 周就能补上，补完之后它就不再是「说不清差什么」的玩具，而是一个**知道自己有多强、
也知道下一步往哪走**的实验平台。
